# Agentic AI Library

## 170 Multi-Agent AI Reference Architectures Across 15 Domains

**A practical engineering atlas for building, studying, evaluating, and governing agentic AI systems.**

This library brings together **170 standalone multi-agent systems** spanning executive intelligence, AI engineering, software, healthcare, neuroscience, robotics, science, education, legal and compliance, manufacturing, marketing, creative work, public-sector systems, finance and risk, and personal productivity.

> **170 systems. 15 domains. One engineering philosophy: build agents that can reason and coordinate together without surrendering human authority.**

## Why this library stands apart

This is not a list of prompts or agent names. The collection is organized as an engineering reference for **multi-agent architecture** and increasingly standardized around production-oriented patterns:

- specialized agents with explicit responsibilities
- orchestrated multi-agent workflows rather than a single monolithic assistant
- deterministic tools and structured state where appropriate
- evidence, provenance, and traceability
- memory and context boundaries
- observability and explicit failure states
- evaluation and held-out scenarios
- safety, privacy, security, and domain-specific governance
- fail-closed controls for consequential workflows
- explicit human approval and protected-action boundaries

The goal is to make each repository useful both as a **standalone reference implementation** and as part of a broader atlas of how agentic systems can be designed across radically different domains.

## Reference architecture pattern

Many systems in the library follow a shared engineering pattern while adapting controls to their domain:

```text
User / System Input
        |
        v
Specialized Agent Team
        |
        v
Orchestration + State + Tools
        |
        v
Evidence / Domain Review
        |
        v
Safety + Governance Gates
        |
        v
Evaluation + Observability
        |
        v
Human-Approved Output / Action
```

The architecture intentionally separates **decision support** from **consequential execution**. Higher-impact systems require stronger evidence, narrower authority, explicit review, and human control.

## Gold Standard direction

The library is being normalized toward an **L3 Gold Standard** for governed multi-agent systems. Gold Standard repositories emphasize:

1. real executable multi-agent orchestration
2. explicit agent responsibilities and domain boundaries
3. deterministic governance checks
4. fail-closed behavior when required reviews are missing
5. protected actions that remain outside autonomous authority
6. direct governance tests
7. held-out evaluation scenarios
8. observability and provenance
9. multi-version CI verification
10. comprehensive engineering documentation

This standard is intentionally stricter for healthcare, legal, finance, public-sector, safety, security, robotics, and other consequential domains.

L3 is a project-defined engineering maturity designation. It is not a legal, regulatory, safety, security, or production certification. At the time of this release, only systems recorded in the [public maturity registry](docs/MATURITY_REGISTRY.md) may be described as L3. A repository link, local package, flagship selection, or Demo Lab simulation does not establish L3 status by itself.

## For researchers

Use the library to compare how agent decomposition, orchestration, review gates, evidence requirements, memory, evaluation, and authority boundaries change across domains. The F01-F170 numbering provides a stable map for discussing individual reference systems.

## For engineers

Use individual repositories as starting points for architecture exploration, prototypes, test harnesses, governance patterns, evaluation design, or domain-specific agent decomposition. Production deployment requires independent validation, security review, domain expertise, and adaptation to the actual operating environment.

## For educators and students

The collection can be used to study multi-agent AI through concrete domains rather than only abstract agent examples. Compare neighboring systems, identify shared architectural primitives, examine domain-specific safety boundaries, and design improved orchestration or evaluation strategies.

## For organizations

The library demonstrates an important distinction: **an AI system can assist with analysis and coordination without automatically receiving authority to execute consequential actions.** Organizations can use these patterns to reason about decision rights, approval gates, auditability, and human accountability before deploying agentic workflows.

## Responsible use

These repositories are reference architectures and engineering examples. They are not substitutes for licensed professionals, authorized decision makers, organizational controls, regulatory review, clinical judgment, legal advice, financial advice, security authorization, or human accountability.

Sensitive systems should preserve least privilege, data minimization, evidence requirements, qualified review, explicit authorization, auditability, rollback where applicable, and clear escalation paths.

## Research and engineering philosophy

The central question behind this collection is not simply:

> **What can an AI agent do?**

It is also:

> **How should multiple intelligent agents coordinate, what evidence should they require, where should their authority stop, and when must a human remain in control?**

That distinction becomes more important as agentic systems move from generating text to participating in real workflows.
