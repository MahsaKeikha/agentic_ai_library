EVIDENCE BEFORE AUTHORITY

Know exactly what each claim proves.

The Atlas separates architecture, implementation, testing, simulation, independent review, and real-world deployment. These are different kinds of evidence and they should never be presented as interchangeable.

Trust grows when the boundary of a claim is visible.

A system is promoted only for the evidence it can show. Missing evidence remains a gap, not a marketing phrase.

THE EVIDENCE LADDER

Six labels with six different meanings.

01

Cataloged reference

A documented multi-agent architecture with a defined domain purpose. Inclusion does not imply production readiness.

02

Structured implementation

Repository structure exposes roles, orchestration, tools, state, safety boundaries, tests, and documentation where applicable.

03

L3 Gold Standard

A project-defined engineering maturity status backed by recorded commit, CI, and benchmark evidence. It is not a regulatory certification.

04

Interactive simulation

A browser demonstration using synthetic scenarios to make coordination, evidence, failure modes, and human approval visible.

05

Independent review

A review claim requires a named or authorized reviewer, defined scope, date, findings, and disposition. No review is implied without that record.

06

Deployment evidence

A deployment claim requires an authorized organization, bounded use case, operating context, measured outcome, and permission to publish.

CORRECTION AND REVIEW

The reference should become stronger when challenged.

Technical corrections

Document the affected system, claim, evidence, expected behavior, and reproduction path. Accepted corrections remain visible in repository history.

Independent review

Reviewers may assess architecture, evaluation, security, domain boundaries, documentation, or reproducibility without endorsing the whole collection.

Adoption records

Teaching, research, and organizational use are recorded only with a verifiable source or explicit permission from the adopting organization.

Release evidence

Material releases identify the source commit, affected systems, completed tests, known limitations, and any maturity impact.

Security findings

Unpatched vulnerabilities follow private responsible disclosure rather than public issues.

Commercial confidentiality

Public evidence supports scrutiny without publishing client information, private delivery methods, or organization-specific implementation details.
