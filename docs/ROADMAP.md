## Engineering-grade checklist

Every unified system should satisfy [`systems/STANDARD.md`](../systems/STANDARD.md) and include architecture/scope, agent roles, orchestration, state or memory expectations, safety boundaries, evaluation, human gates, failure handling, example workflow, integration points, and deployment notes appropriate to its maturity.

## Build policy

- Prefer working offline demos over empty README-only packages.
- Do not invent missing material facts.
- Sensitive domains keep explicit limitations and escalation requirements.
- Stable IDs never renumber once released.
- F27 onward use the unified `systems/` architecture unless a system is intentionally promoted to a standalone flagship.
