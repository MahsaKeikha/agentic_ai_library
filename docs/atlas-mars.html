        03 / WHAT MAKES THIS A WORKING ENGINEERING DEMO

        The runtime is more than an animation.

        The browser experience is driven by a separate deterministic mission engine with a tool registry, explicit side-effect classes, policy enforcement, invariant checks, failure injection, decision packages, and automated tests.

        01

        Deterministic state machine

        Each scenario produces structured state, agent handoffs, tool calls, decisions, blockers, warnings, and a final status that can be exported and replayed.

        02

        Fail-closed tool policy

        Every tool is classified as read-only, analysis, bounded autonomy, or protected. Protected actions are denied and recorded rather than silently executed.

        03

        Runtime invariants

        Reserve floors, stale model state, contradictory inventory, unsafe CO2 trends, and protected-action requests are explicit machine-checkable conditions.

        04

        CI-tested behavior

        The repository runs Node-based tests for nominal recovery, communications loss, adversarial blocking, protected-action denial, secondary faults, and export integrity.

        04 / PRODUCTION EVOLUTION

        The public runtime is intentionally safe to inspect. A real deployment would replace only the adapters.

        The orchestration, authority model, event schema, evidence model, and evaluation logic can remain conceptually stable while synthetic adapters are replaced by authenticated server-side interfaces.

        TELEMETRY ADAPTERS

        Read real approved state

        Server-side connectors to telemetry, historian, asset registry, model registry, inventory, and robot fleet systems with explicit scopes and freshness metadata.

        MODEL / AGENT SERVICE

        Model-backed specialists behind contracts

        Specialists can use approved model providers, but outputs must conform to structured schemas and remain subordinate to deterministic gates and tool permissions.

        DURABLE STATE + AUDIT

        Persist every material event

        Use an append-only event store, project/run IDs, identity, provenance, retention policy, and tamper-evident operational logs.

        AUTHORITY + SAFETY

        Separate credentials from reasoning

        Protected tools require independent authorization, least privilege, policy checks, qualified approval, and environment-specific change control.
